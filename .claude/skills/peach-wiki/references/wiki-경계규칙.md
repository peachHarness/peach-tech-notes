# wiki entities vs docs/기능별설명 경계 규칙

> INGEST / INGEST-INCREMENTAL 시 "이 내용을 wiki에 쓸 것인가, docs/기능별설명(feature-docs)에 쓸 것인가"를 판단하는 기준.
> 경계 규칙 없이 양쪽에 쓰면 처리흐름이 중복 작성되어 유지비만 늘어난다 — 한 지식은 한 곳에만 쓴다.

## 역할 계층

```
[검색]  qmd              ← wiki·feature-docs·소스코드 공통 피검색 대상
          ↓
[지도]  docs/wiki/       ← 프로젝트 전체 아키텍처·모듈 간 관계·횡단 개념
          ↓
[심층]  docs/기능별설명/  ← 단일 기능 암묵지·설계결정·TDD 가이드 (수정 전 컨텍스트)
```

세 도구는 계층이 달라 기능 중복이 아니다. wiki는 "지도", feature-docs는 "심층"이다.

## 판단표

| 내용 | 기록 위치 |
|------|----------|
| 모듈 간 관계, 의존성, 데이터 흐름 (특정 기능에 속하지 않는 지식) | `docs/wiki/entities/` |
| 아키텍처 패턴, 도메인 개념 | `docs/wiki/concepts/` |
| 의사결정·트레이드오프 (프로젝트 수준) | `docs/wiki/synthesis/` |
| 프로젝트 전체 온보딩 맥락 | `docs/wiki/` |
| 단일 기능의 처리 흐름, 에러코드, 권한 체크, 이력 기록 | `docs/기능별설명/{카테고리}/{기능}/` |
| 설계결정(ADR): 매직넘버 이유, 함수명 변경 배경, 컬럼 크기 근거 | `docs/기능별설명/...` |
| TDD 가이드: 테스트 케이스 목록, 실행법, 함정 | `docs/기능별설명/...` |
| 버그픽스 이력 | `docs/기능별설명/...` |

## 중간 지점 처리 (교차 링크, 중복 서술 금지)

- wiki `entities/module-이름.md`에는 기능 개요만 쓰고 `"심화는 docs/기능별설명/{카테고리}/{기능}/ 참조"` 링크를 남긴다.
- feature-docs `{기능}-개요.md`에는 `"모듈 간 관계는 docs/wiki/entities/ 참조"` 역참조를 남긴다.
- 같은 처리 흐름을 양쪽에 서술하지 않는다. 발견하면 feature-docs를 정본으로 두고 wiki 쪽은 링크로 축약한다 (LINT에서 정리).

## AGENTS.md 섹션 소유권 (충돌 방지)

`node-setup-harness`와 `peach-wiki INIT`은 같은 AGENTS.md를 수정하므로 소유권을 분리한다.

| AGENTS.md 섹션 | 소유 스킬 |
|---------------|-----------|
| 공통 원칙, 네이밍, 타입, 보안 | `node-setup-harness` |
| wiki 참조, wiki 복리 게이트, qmd 인덱스 | `peach-wiki INIT` |
| 기능별 가이드, 모듈별 규칙 | 해당 스킬 |

원칙: 자신이 추가한 섹션만 수정하고, 다른 스킬이 추가한 섹션은 건드리지 않는다.
