# 탭 선택 패턴

> 탭 확정 절차·강제 게이트·origin 재사용 트리·targetId 조회 명령의 SoT는
> `실행환경-공통게이트.md` §4~§6과 SKILL.md 게이트 3·부트스트랩이다.
> 이 문서는 재서술 없이 **왜 그렇게 정했는지**(판단 근거)와 도구별 선택 기준만 담는다.

## 핵심 기준

탭 index는 실행 기준이 아니다. E2E 브라우저 작업은 CDP `targetId`를 안정 ID로 사용한다.

| 도구 | 안정 ID | 용도 |
|------|---------|------|
| pwx.js / Playwright / e2e.sh | CDP `targetId` (`E2E_TAB_ID`) | 탐색, 시나리오 실행, suite 실행, QA 재현 |
| playwright-cli | 세션 + 코드 내부 targetId 재확인 | snapshot/click ref가 필요할 때만 |
| agent-browser opt-in | `tabId` 또는 label | 명시 요청 시 단일 세션 읽기 전용 확인 |

## index와 current tab이 흔들리는 이유

CDP `/json` 배열 순서와 브라우저 UI 탭 순서는 탭 생성/닫기/이동에 따라 변한다. 시간차 실행에서 `--tab N`을 반복 사용하면 엉뚱한 탭을 잡을 수 있다. `--tab N`은 실행 시작 시점에 N번째 page를 `E2E_TAB_ID`로 변환하는 하위 호환 편의 입력으로만 쓴다 — 반복 루프 금지.

또한 `agent-browser`는 daemon의 current tab/frame 상태를 공유한다. 여러 AI 세션이 같은 CDP에 동시에 `tab <label>`과 `eval/click/fill`을 보내면 current tab이 서로 덮인다(2026-06-01 실측: A/B 탭 병렬 반복에서 cross-tab 실행 50/100).

## origin 매칭 기준의 근거

같은 origin(scheme+host+port) 탭 재사용 규칙(트리는 공통게이트 §4)을 origin으로 정한 이유:

- `host`만 보면 `localhost:3000`과 `localhost:3001`을 같은 탭으로 오인한다.
- `origin+path` 완전일치는 너무 엄격하다 — SPA에서 `/login`→`/dashboard`로 넘어간 탭은 path가 달라 매번 새 탭이 된다.
- 동일 origin 탭이 2개 이상이면 자동 선택하지 않는다. 서로 다른 계정·상태일 수 있고 CDP는 어느 탭이 맞는지 알 수 없다 — 사용자 확인이 유일한 안전 경로다.

## 선택 기준

| 상황 | 권장 방식 | 이유 |
|------|----------|------|
| 단발 DOM 확인·조작 | `pwx.js <targetId>` (SKILL.md 부트스트랩) | 세션 생성 없음 → 기존 탭 무손상 |
| 단위 시나리오 실행 | `E2E_TAB_ID` + `./e2e.sh run` | targetId로 정확한 탭 지정 |
| suite/QA 재현 | `E2E_TAB_ID` | 시간차 실행 중 index 드리프트 방지 |
| 여러 AI 세션 병렬 조작 | targetId page (pwx.js 또는 connect()) | current tab 공유 상태 제거 |
| 임시 단발 실행 | `--tab N` | 즉시 targetId로 변환되는 경우만 |
| 사용자가 명시한 단일 읽기 | agent-browser `tabId`/label | opt-in만 (아래) |

`playwright-cli -s=<세션> open`을 앞에 붙이는 예전 방식은 쓰지 않는다 — 기존 탭 하나를 `about:blank`로 덮어쓴다(실측 2회 재현, 상세: `playwright-cli-명령어.md`).

## agent-browser opt-in 한계

허용 조건(모두 만족): 사용자 명시 요청 / 단일 AI 세션 / 읽기 전용 DOM 확인 / click·fill·press·submit·운영 데이터 변경 없음 / 실행 전 병렬 세션 간섭 가능성 보고. 병렬 실행·장시간 suite·QA 재현·자동수정 루프는 위 cross-tab 실측 때문에 Playwright `targetId` 방식만 사용한다.
