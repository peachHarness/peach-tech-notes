# E2E 인프라 셋업·배포

> 대상 프로젝트에 E2E 인프라를 설치/갱신하는 절차. 구 `peach-e2e-setup` 스킬 본문 (2026-07-29 통합).
> 로드 조건: 초기 설치 요청 시, 또는 인프라 버전 게이트(`실행환경-공통게이트.md` §2) 불일치 시.
> 인프라 코드 SoT: 이 문서와 같은 폴더의 `infra/`. **`infra/`는 대상 프로젝트 `e2e/`에 설치되는 구조와 1:1로 같다** — 하위 경로를 그대로 복사하면 배포가 끝난다.
>
> ```
> infra/                 →  e2e/
>   e2e.sh                    e2e.sh          진입점 CLI (setup/chrome/list/run/status)
>   lib/                      lib/            e2e.sh가 require하는 내부 모듈 + 그 모듈의 테스트
>     connect.js                connect.js
>     connect.test.js           connect.test.js      ← 대상 스크립트 옆에 둔다
>     run-scenario.js           run-scenario.js
>     run-scenario.test.js      run-scenario.test.js
>     selector.js               selector.js
>   tools/                    tools/          사람·AI가 직접 부르는 단독 CDP 도구
>     pwx.js                    pwx.js
>     pwc.sh                    pwc.sh
>     pwt.js                    pwt.js
> ```
>
> 설치 대상이 아닌 스킬 전용 자산은 `infra/` 밖에 둔다: `../샘플시나리오/gmail-메일목록.js`(동작 검증용 샘플, `e2e/시나리오/`로 조건부 복사).
>
> `tools/pwx.js`는 e2e 인프라 없이 스킬 폴더에서 바로 실행할 수 있다. `list`/`title`은 Node.js 18+, raw CDP `eval`은 Node.js 22+, 실제 조작은 전역 `playwright-core`가 필요하다. 배포는 프로젝트에서 `./e2e/tools/pwx.js`로 짧게 부르기 위한 편의다.

## 전제조건

- **대상 프로젝트 루트**에서 실행 (peach-harness 자체가 아닌 대상 프로젝트)
- macOS 또는 Windows(Git Bash)

## Step 1: npm 글로벌 도구 설치 체크

```bash
command -v agent-browser && echo "✅ agent-browser" || echo "❌ agent-browser 미설치"
command -v playwright-cli && echo "✅ playwright-cli" || echo "❌ playwright-cli 미설치"
node -e "require('playwright-core')" 2>/dev/null && echo "✅ playwright-core" || echo "❌ playwright-core 미설치"
```

미설치 시 안내(한 번에): `npm install -g agent-browser @playwright/cli playwright-core`
**자동 설치하지 않는다** — 명령어를 안내하고 사용자 확인을 받는다.

## Step 2: Chrome Beta 설치 확인

```bash
# macOS
ls -d "/Applications/Google Chrome Beta.app" 2>/dev/null && echo "✅" || echo "❌ 미설치"
# Windows (Git Bash)
[ -f "/c/Program Files/Google/Chrome Beta/Application/chrome.exe" ] && echo "✅" || echo "❌ 미설치"
```

미설치 시: https://www.google.com/chrome/beta/ (기본 Chrome과 동시 실행 가능, E2E 전용 분리)

> `e2e.sh`가 `uname -s`로 OS를 감지해 Chrome 경로를 분기한다. 실행 규칙(포트 9333 + 고정 프로필 필수)은 `실행환경-공통게이트.md` §1을 따른다.

## Step 3~4: e2e/ 폴더 생성 + 인프라 코드 배포

```bash
mkdir -p e2e/lib e2e/tools
```

`infra/`의 코드를 Read로 읽어 Write로 **같은 상대경로**에 작성한다. **인프라 9개는 항상 최신으로 덮어쓴다.**

| 소스 (references/infra/) | 대상 (e2e/) | 역할 |
|---------------------------|-------------|------|
| `e2e.sh` | `e2e/e2e.sh` (chmod +x) | 진입점 CLI |
| `lib/connect.js` | `e2e/lib/connect.js` | CDP 연결·탭 확정·evidence 수집 |
| `lib/connect.test.js` | `e2e/lib/connect.test.js` | 마스킹·버전 동기화 회귀 테스트 |
| `lib/run-scenario.js` | `e2e/lib/run-scenario.js` | 시나리오 실행 watchdog |
| `lib/run-scenario.test.js` | `e2e/lib/run-scenario.test.js` | watchdog(무한 대기 차단) 회귀 테스트 |
| `lib/selector.js` | `e2e/lib/selector.js` | 탭 선택 TUI |
| `tools/pwx.js` | `e2e/tools/pwx.js` (chmod +x) | 기본 도구 — 탭 조회·DOM 읽기·Playwright 조작 |
| `tools/pwc.sh` | `e2e/tools/pwc.sh` (chmod +x) | 폴백 — playwright-cli 접근성 트리(`snapshot`) |
| `tools/pwt.js` | `e2e/tools/pwt.js` (chmod +x) | 진단·복구 — attach hang 시 무응답 탭 특정, `--fix`로 비파괴 복구 |

> 테스트(`*.test.js`)는 별도 `test/` 폴더가 아니라 **검증 대상 스크립트와 같은 폴더**에 둔다. `connect.js`를 고칠 때 그 테스트가 바로 옆에 보여야 같이 고치게 된다. `./e2e.sh test`가 `lib/*.test.js`를 실행한다.
>
> `lib/`는 `e2e.sh`가 내부적으로 부르는 모듈이라 직접 실행하지 않는다. `tools/`는 반대로 사람·AI가 직접 부르는 단독 CLI다. 이 구분이 폴더 이름 그대로다.

> **인프라 버전 게이트**: `e2e.sh`와 `lib/connect.js` 상단의 `HARNESS_E2E_VERSION`은 같은 값이다. `peach-e2e-scenario`(단위·suite)와 team-e2e는 실행 전 `./e2e.sh status`의 `E2E_INFRA_VERSION`·`E2E_CDP_PORT`를 읽어 기대 버전 불일치 또는 9222 구버전 포트면 실행을 중단하고 이 절차로 최신 인프라를 갱신한다. 덮어쓰면 게이트가 해소된다. 인프라 코드를 의미 있게 바꿀 때는 두 파일의 `HARNESS_E2E_VERSION`을 함께 올린다.

## Step 5: 시나리오 폴더 + 테스트 시나리오

```bash
# 시나리오 폴더는 없을 때만 생성. 있으면 절대 건드리지 않는다 (사용자 시나리오 보호).
[ -d "e2e/시나리오" ] || mkdir -p "e2e/시나리오"
```

`../샘플시나리오/gmail-메일목록.js` → `e2e/시나리오/gmail-메일목록.js` (동작 검증용):
- 파일 없음 → 복사 (질문 없음)
- 파일 있음 + 동일 → "최신 상태" 스킵
- 파일 있음 + 다름 → diff 요약 후 "업데이트하시겠습니까? (y/N)" — N 기본

## Step 5-b: e2e/.gitignore에 .tmp/ 보장

state 파일·실패 evidence(`e2e/.tmp/`, `e2e/.tmp/evidence/`)에 스크린샷·API 페이로드가 남으므로 커밋 제외가 필수다.

```bash
GITIGNORE="e2e/.gitignore"; LINE=".tmp/"
if [ ! -f "$GITIGNORE" ] || ! grep -qxF "$LINE" "$GITIGNORE"; then
  printf '%s\n' "$LINE" >> "$GITIGNORE"; echo "✅ ${LINE} 추가"
fi
```

## Step 6~7: 실행 권한 + 완료 보고

```bash
chmod +x e2e/e2e.sh e2e/tools/pwc.sh e2e/tools/pwx.js e2e/tools/pwt.js
```

## 레거시 스윗 이전

기존 `docs/e2e-suite/`가 있으면 인프라 배포 뒤 `e2e/스윗/`으로 옮긴다. 양쪽에 같은 상대경로 파일이 있으면 덮어쓰지 않고 충돌 목록을 보고한다. 충돌이 없을 때만 하위 파일을 모두 이동하고, 저장소의 `docs/e2e-suite/` 참조를 새 경로로 갱신한 뒤 빈 기존 폴더만 정리한다. 상세 검증과 보고 항목은 `peach-e2e-scenario/references/suite-scenario-파일구조.md` 5절을 따른다.

완료 보고에 배포 파일 목록과 다음 단계를 안내한다:

```
1. cd e2e && ./e2e.sh setup    — 환경 자동 체크
2. cd e2e && ./e2e.sh chrome   — Chrome Beta CDP 실행 (9333 + 고정 프로필)
3. Chrome Beta 고정 프로필에서 로그인/인증 완료 (사람)
4. cd e2e && ./e2e.sh test   — 인프라 자체 테스트 (Chrome 불필요)
5. cd e2e && ./e2e.sh run 시나리오/gmail-메일목록.js — 동작 검증
```

## 주의사항

- `e2e/시나리오/`와 `e2e/스윗/`이 존재하면 절대 덮어쓰거나 삭제하지 않는다
- 인프라 9개(e2e.sh, lib/ 5개=모듈 3+테스트 2, tools/ 3개)는 항상 덮어쓴다 — `infra/`와 `e2e/`는 같은 하위 경로를 유지한다
- 글로벌 도구 자동 설치 금지 — 안내 후 사용자 확인
- 시나리오 실행은 반드시 `./e2e.sh run` (`node` 직접 실행은 전역 `playwright-core`를 못 찾음 — e2e.sh가 NODE_PATH 설정)
- 인증은 사용자가 고정 프로필에서 직접 완료, AI는 세션만 이어받는다
- dialog 수동 검증 전 상주 daemon 점검: `native-dialog-주의사항.md`
