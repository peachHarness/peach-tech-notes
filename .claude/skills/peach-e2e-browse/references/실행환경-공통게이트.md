# E2E 실행 환경 공통 게이트

> Chrome Beta 실행·인프라 버전 게이트·탭 확정/드리프트 방지·실행 주소 정책의 공유 SoT.
> `peach-e2e-browse` / `peach-e2e-scenario`(단위·suite) / `node-team-e2e`가 공유한다.
> 각 스킬 SKILL.md는 이 문서를 포인터로만 참조하고 본문에 재서술하지 않는다.

## 1. Chrome Beta 실행 불변 규칙

Chrome Beta를 CDP 모드로 실행할 때는 고정 프로필 옵션이 필수다. 프로필 옵션이 빠진 실행은 세션 유지 실패로 간주한다.

- 허용: `cd e2e && ./e2e.sh chrome`
- 직접 실행 시 필수 옵션: `--remote-debugging-port=${E2E_CDP_PORT:-9333}`, `--remote-allow-origins=*`, `--user-data-dir=$HOME/.chrome-beta-e2e-profile`, `--disable-extensions`, 그리고 아래 코드블록의 freeze 방지 4종
- macOS 직접 실행 표준: `/usr/bin/open -na "Google Chrome Beta" --args ...`
- 금지: `open -a "Google Chrome Beta"` 단독 실행, `--args` 없는 `open` 실행, `--user-data-dir` 없는 Chrome Beta 실행, 다른 프로필 경로 임의 사용, 기본 Chrome 또는 다른 브라우저 우회

```bash
/usr/bin/open -na "Google Chrome Beta" --args \
  --remote-debugging-port=${E2E_CDP_PORT:-9333} \
  "--remote-allow-origins=*" \
  "--user-data-dir=${E2E_CHROME_PROFILE_DIR:-$HOME/.chrome-beta-e2e-profile}" \
  --disable-extensions --no-first-run --no-default-browser-check \
  --disable-renderer-backgrounding \
  --disable-background-timer-throttling \
  --disable-backgrounding-occluded-windows \
  --disable-features=CalculateNativeWinOcclusion
```

> ⚠️ 뒤 4개 플래그는 **필수**다. 빠지면 백그라운드 탭 렌더러가 freeze되어 §5-1의 `PLAYWRIGHT_ATTACH_TIMEOUT`이 반복 발생한다. `e2e.sh chrome`은 이미 이 4개를 붙여 실행하므로, 직접 실행 명령에서만 누락되지 않도록 주의한다.
> 실측 2026-08-17(Chrome Beta 152.0.7977.42): 이 플래그 없이 기동된 Chrome Beta에서 page 타깃 10개 중 5개가 freeze되어 attach가 전면 차단됐다. 실행 중 인스턴스의 플래그 누락은 `./e2e.sh status`가 `E2E_BROWSER_FLAGS=missing`으로 보고한다(1.2.8+).

> 인증/2차 인증이 필요하면 AI가 직접 처리하지 않는다. 사용자가 Chrome Beta 고정 프로필에서 먼저 로그인/인증을 완료하도록 안내한 뒤 같은 프로필 세션을 이어받는다.
> 브라우저 디버깅이 비정상이면 OS 레벨 우회(`open -a`, 다른 브라우저 실행, 다른 프로필 경로 사용)를 하지 않는다. 상태를 보고하고 중단한다.

## 2. 인프라 버전 게이트 (실행 전 필수)

실행 전에 설치된 e2e 인프라(`e2e.sh`/`lib/connect.js`)가 최신 계약 버전인지 확인한다. 구버전 인프라는 실패 evidence 자동 수집·마스킹·탭 고정 등 최신 규칙을 못 지켜 검증 결과를 신뢰할 수 없다.

- 기대 버전(EXPECTED): **`1.2.9`** (1.2.8의 Chrome Beta 검증·attach hang 복구·watchdog + `setDialogHandler` 핸들러의 'No dialog is showing' 경합 방어)
- 기대 포트(EXPECTED_PORT): **`9333`**
- 설치 버전(ACTUAL): `./e2e.sh status` 출력 첫 줄 `E2E_INFRA_VERSION=<버전>`에서 읽는다.
- 설치 포트(ACTUAL_PORT): `./e2e.sh status` 출력의 `E2E_CDP_PORT=<포트>`에서 읽는다.

판정:
- `E2E_INFRA_VERSION`이 없거나(`unknown`/출력 없음) ACTUAL이 EXPECTED와 **다르면**: 실행을 **중단**하고 `peach-e2e-browse/references/셋업-배포.md` 절차로 최신 인프라를 갱신한다. 갱신 후 다시 워크플로우로 돌아온다.
- `E2E_CDP_PORT`가 없거나 ACTUAL_PORT가 `9222`이면: 구버전 9222 인프라로 간주하고 실행을 **중단**한 뒤 같은 절차로 `e2e.sh`/`connect.js`/`selector.js`를 갱신한다.
- `E2E_BROWSER_STATE=stale`이면: CDP HTTP가 정상이어도 실행본과 설치본 버전이 다르므로 실행을 **중단**한다. 탭 세션 영향을 보고하고 사용자 승인 후 Chrome Beta를 재시작한다.
- ACTUAL = EXPECTED: 정상 진행.

`E2E_CDP_HTTP_STATUS=ok`는 `/json/version` 응답만 증명한다. `E2E_PLAYWRIGHT_STATUS=unchecked`는 정상 초기값이며 실제 조작의 `connectOverCDP` 성공 전에는 Playwright 정상으로 판정하지 않는다.

> 버전 비교는 semver 기준(major.minor.patch). EXPECTED는 스킬이 의존하는 인프라 기능이 추가될 때 함께 올린다. 사용자가 명시적으로 "구버전 강행"을 지시한 경우에만 게이트를 건너뛴다.

### CDP 미연결 시 자동 복구

`status`에서 `❌ Chrome CDP 미연결`이 보이면 아래 순서로 자동 복구를 먼저 시도한다.

1. `cd e2e && ./e2e.sh chrome` 실행
2. `cd e2e && ./e2e.sh status` 재확인
3. 여전히 미연결이면 사용자에게 같은 명령의 수동 실행을 안내한다

> `./e2e.sh chrome`은 고정 프로필(`$HOME/.chrome-beta-e2e-profile`)로 Chrome Beta를 실행하는 표준 경로다. 이 명령 대신 직접 Chrome을 실행할 때도 `--user-data-dir` 옵션을 생략하지 않는다.

## 3. 실행 주소 정책

E2E 실행 주소는 런타임 컨텍스트다. 시나리오 `.js`·suite md에는 절대 URL을 저장하지 않는다.

| 위치 | 처리 |
|------|------|
| 사용자 입력 URL, `base_url`, 접속 주소 | 이번 실행 탭 확정에만 사용 |
| handoff의 `base_url`, `e2e_tab` | 이번 chain 실행 컨텍스트로만 사용 |
| `BASE_URL`, `E2E_BASE_URL`, `E2E_BASE` | 실행 시점 환경값으로만 사용 |
| 시나리오 `.js` | 현재 탭, 상대 경로, 조건부 이동만 사용. 절대 URL 저장 금지 |
| suite md | "로그인 완료된 대상 환경" 같은 조건만 기록. 절대 URL 저장 금지 |
| 실패 보고 | 실제 URL은 실행 컨텍스트/진단 정보로만 보고. 파일에 고정하지 않음 |

주소가 없으면 실행 중인 프론트 후보를 탐지한다(`lsof -iTCP -sTCP:LISTEN -n -P`, 흔한 프론트 포트 `3000`/`5173`/`5174`/`8080`/`8000`/`4200`의 `curl` 응답, `package.json` scripts, Vite/Next/Vue 설정). 명확한 후보가 있으면 그 URL을 이번 실행 컨텍스트로 사용한다. 후보가 둘 이상이거나 연관성이 불명확하면 자동 선택하지 않고 사용자에게 확인한다. 이미 사용자가 띄운 서버는 종료하지 않고, AI가 직접 띄운 프로세스만 작업 후 정리한다. 운영/외부 주소는 자동 기동 대상이 아니다.

## 4. 실행 대상 탭 확정 순서

1. 사용자 URL, `base_url`, 접속 주소가 있으면 CDP `/json/list`에서 같은 origin(scheme+host+port) 탭을 먼저 찾아 1개면 `targetId`로 재사용하고, 없으면 Playwright로 새 탭을 만든다. **2개 이상이면 멈추고** 사용자에게 `targetId`/title 확인을 받는다.
2. handoff의 `e2e_tab` 또는 `base_url`이 유효하면 재사용한다.
3. 주소가 없으면 실행 중인 프론트 후보를 탐지하고, 명확한 후보가 있으면 그 URL을 이번 실행 컨텍스트로 사용한다.
4. 주소도 실행 중 후보도 없으면 실행 후보 명령을 분석해 보고하고 사용자 위임/승인 후 dev 서버를 기동한다.
5. 위 조건이 모두 불명확할 때만 탭 목록을 사용자에게 보여주고 작업 `targetId`/title을 확인한다.

어느 경우든 확정 직후 title+href를 검증한다.

```bash
PWX=<peach-e2e-browse 경로>/references/infra/tools/pwx.js
$PWX list                        # targetId<TAB>url<TAB>title — 여기서 origin이 같은 탭을 센다
$PWX new "https://URL"           # 0개일 때: 탭 생성 + title 검증을 한 왕복으로
$PWX "$TARGET_ID" title          # 재사용할 때: 검증만
$PWX "$TARGET_ID" eval "({title:document.title,href:location.href})" # raw CDP 상태 확인

# node를 못 쓰는 환경 fallback
TARGET_ID=$(curl -s http://127.0.0.1:${E2E_CDP_PORT:-9333}/json | jq -r '.[] | select(.type=="page" and .url=="<검증된 URL>") | .id' | head -1)
```

> 탭 생성에 `playwright-cli open`을 쓰지 않는다. 새 탭을 만드는 대신 **기존 탭 하나를 `about:blank`로 덮어쓴다**(실측 2회 재현). 고정 프로필에는 사용자가 쓰던 탭이 살아 있으므로 이건 데이터 손실이다.

## 5. targetId 고정 / 탭 드리프트 방지 (루프 필수)

- 실행 탭이 확정되면 CDP `targetId`를 기록하고, 이번 실행 동안 `E2E_TAB_ID`로 고정한다.
- suite/QA는 여러 Step을 시간차로 순차 실행하므로 인덱스(`--tab N`)는 도중에 흔들린다. 사람이 탭을 옮기거나 다른 AI 세션이 탭을 추가하면 같은 N이 다른 탭을 가리킨다. `targetId`는 탭 위치와 무관하므로 탭이 닫히지 않는 한 끝까지 같은 탭을 잡는다.
- 여러 AI 세션이 같은 Chrome Beta CDP를 병렬 조작하는 경우 current tab 상태를 공유하는 도구에 의존하지 않는다. 병렬 조작은 Playwright `targetId` page 또는 `E2E_TAB_ID`만 사용한다.
- targetId 고정 직후 `pwx.js title` 또는 `pwx.js eval` raw CDP로 `document.title + ' | ' + location.href`를 1회 검증한다. 예상과 다르면 `./e2e.sh status` 재출력 후 재선택. **검증 통과 후에는 매 Step마다 사람에게 탭을 다시 묻지 않는다.**

> 상세 탭 선택 기준: `탭-선택-패턴.md`

### 5-1. Playwright attach timeout 복구

`PLAYWRIGHT_ATTACH_TIMEOUT`은 시나리오 오류가 아니다. 같은 attach를 반복하거나 임의 Node 프로세스를 일괄 종료하지 않는다.

**근본 원인(실측)**: `connectOverCDP`는 내부적으로 `Target.setAutoAttach`로 모든 page 타깃에 자동 attach한다. 백그라운드 탭의 렌더러가 Chrome에 의해 freeze되면 그 탭 하나의 attach가 응답하지 않고, 무응답 탭 하나가 전체 attach를 막는다. **타임아웃을 늘리는 것은 해결책이 아니다.** 근본 예방은 §1의 Chrome 기동 플래그 4종이며, 그 플래그 없이 이미 떠 있는 Chrome에는 재시작해야 적용된다.

**1순위: `pwt.js --fix` (비파괴, 사용자 승인 불필요).**

```bash
node e2e/tools/pwt.js --fix   # 무응답 탭을 activateTarget으로 복구 (없으면 스킬의 references/infra/tools/pwt.js)
node e2e/tools/pwt.js         # 진단만 (읽기 전용)
```

바뀌는 것은 탭 포커스뿐이고 탭을 닫지 않으며, 원래 보이던 탭으로 포커스를 되돌린다. **복구되면 승인 없이 진행한다.** 무응답이 남으면 exit 1로 보고하므로 그때만 아래 절차로 넘어간다.

실측 근거:

| 항목 | 값 |
|---|---|
| `Target.activateTarget` 복구 | **5/5** (2026-08-17, Chrome Beta 152.0.7977.42, page 타깃 10개 중 5개 freeze) |
| 복구 후 `connectOverCDP` | 684ms 성공 |
| `Page.setWebLifecycleState{active}` 복구 | **0/5** — 호출은 성공하지만 복구되지 않는다. 대안으로 쓰지 않는다 |
| 진단 소요 | 병렬 181ms(정상 10개). 직렬이면 무응답 수 × timeout(무응답 5개 ≈ 25초) |

> 이전 판에는 "`Target.activateTarget`으로 되살리는 시도는 실측에서 전부 실패했다 — 시도하지 않는다", "비파괴 복구 수단 없음"이라고 적혀 있었다. **두 문장 모두 철회한다.** 재실측에서 5/5 복구됐다.
> 단 만능은 아니다. Chrome이 스스로 강등한 백그라운드 렌더러는 되살아나지만, 렌더러가 실제로 멈춘 경우(무한 루프·커널 정지)는 풀리지 않는다 — 격리 재현 검증(`tools/e2e-verify/run-e2e-frozen-tab-verification.mjs`)이 이 경우 `--fix`가 거짓 성공 대신 exit 1을 내는지 고정하고 있다.

`--fix`로도 무응답이 남을 때만 아래로 넘어간다.

1. `lsof -iTCP:${E2E_CDP_PORT:-9333} -sTCP:ESTABLISHED -n -P`로 CDP 클라이언트를 확인한다.
2. 각 PID를 `ps -p <PID> -o command=`로 확인한다.
3. `agent-browser ... daemon.js`, `cliDaemon.js`, `run-driver`처럼 **명령이 확인된 CDP 클라이언트만** `kill -TERM <PID>`로 종료한다. 2초 뒤 같은 PID가 살아 있을 때만 `kill -KILL <PID>`를 사용한다.
4. 그래도 남으면 무응답 탭의 영향과 재시작 대상을 보고하고, **사용자 승인 후** 해당 탭 종료 또는 고정 프로필 Chrome Beta 재시작으로 복구한다.
5. `status` → `pwx.js list` → `title`/`eval` → 실제 Playwright 조작 1회의 순서로 복구를 검증한다.

Tunnelblick 또는 명령이 확인되지 않은 일반 Node 프로세스는 CDP 포트의 정확한 클라이언트라는 증거가 없으면 종료하지 않는다.

## 6. 민감 세션 / 쓰기 조작 승인

Google 로그인, OAuth, 관리자 콘솔, 결제, 기존 Chrome Beta 프로필 세션 유지가 핵심인 작업은 새 탭 생성과 상태 확인까지만 자율 수행하고, 실제 입력/제출/설정 변경/결제/운영 데이터 변경은 사용자 확인 후 시작한다. URL 또는 작업 탭이 확정되기 전에는 실행하지 않는다.

## 7. 파일 업로드 Step

시나리오 코드에서 `page.setInputFiles()` 또는 file input 조작이 필요하면 OS 네이티브 파일 다이얼로그 차단을 위해 `Page.setInterceptFileChooserDialog` 방식을 사용한다. CDP Escape 키 이벤트로는 macOS 네이티브 다이얼로그를 닫을 수 없다.

> 상세: `SPA-프레임워크-입력패턴.md §3`
